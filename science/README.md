# MarsTwin science pipeline

Solo build · **six dimensions** · thermal-cycling + mobility use case · **null beats fake numbers**.

The science layer is a Python pipeline that reads local profiles, enriches Earth cells with external observations, scores them against the Moon and Mars targets, validates the known analogs, and writes static JSON for the frontend.

---

## Quick run

```bash
# from repo root
pip install -r science/requirements.txt
python science/scripts/run_pipeline.py
```

The run:

1. Loads `science/profiles/`.
2. Asserts target-profile contracts.
3. Syncs profiles to `apps/web/public/data/`.
4. Fetches NASA POWER air climatology and MODIS NDVI (cached under `science/cache/`).
5. Scores every cell for both destinations.
6. Runs the known-analog validation gate.
7. Builds candidate cards and the data manifest.
8. Writes `apps/web/public/data/*.json`.

`--skip-power` is the offline path: it reuses the POWER and NDVI caches and makes no external science calls.

## Commands

```bash
# Normal run (network allowed; caches reused when present)
python science/scripts/run_pipeline.py

# Offline / cached run
python science/scripts/run_pipeline.py --skip-power

# Force a refetch
python science/scripts/run_pipeline.py --force-power
python science/scripts/run_pipeline.py --force-ndvi

# Choose the MODIS sample year
python science/scripts/run_pipeline.py --ndvi-year 2025
```

Optional imagery fetchers (frontend assets, not scoring inputs):

```bash
python science/scripts/fetch_site_imagery.py     # Esri site thumbnails + world.jpg
python science/scripts/fetch_nasa_imagery.py     # Mars/Moon/analog NASA imagery
```

Optional real slopes (needs local DEMs and `rasterio`):

```bash
python science/scripts/compute_slopes_20m.py \
  --earth-dem dems/srtm_atacama.tif --aoi cell_atacama \
  --jezero-dem dems/jezero_20m.tif \
  --lola-dem dems/lola_spole.tif

python science/scripts/compute_slopes_20m.py --jezero-dem dems/jezero_20m.tif --apply
python science/scripts/run_pipeline.py --skip-power
```

## Rules locked in code

| Rule | Implementation |
|------|----------------|
| Slopes null until 20 m DEM | `compute_slopes_20m.py` (Horn 3x3, shared baseline) writes values + provenance; contract rejects unsourced slopes |
| Lunar mineralogy uncitable | `value: null` + use-case weight `0` |
| NDVI sourced or null | `lib/ndvi.py` MOD13Q1 250 m annual mean; failed fetch / missing coverage sets `vegetation_ndvi` to null, never a stub |
| Air↔air thermal | POWER T2M vs MEDA ~60 K at Jezero; MODIS LST is a separate ground track |
| PSR ~40 K | Gap report hard limit, not an Earth similarity score |
| No silent null fill | Scoring excludes null dimensions and renormalises weights |

## Outputs

| File | Contents |
|------|----------|
| `apps/web/public/data/manifest.json` | Provenance: run date, pipeline version, counts, NDVI vintage, slope status, validation, sources, imagery paths |
| `apps/web/public/data/usecases.json` | Use case and weights |
| `apps/web/public/data/targets.json` | Moon/Mars target profiles |
| `apps/web/public/data/known_analogs.json` | Control group |
| `apps/web/public/data/coarse_results.json` | Every cell × destination score and rank |
| `apps/web/public/data/candidates.json` | Promoted field cards (transfers, tests, breaks, gaps) |
| `apps/web/public/data/method.json` | Method text, transforms, exclusions, limitations |

`manifest.json` is generated by `lib/manifest.py` and is the frontend's source of truth for the data run. It records the NDVI year and the list of cells with data/missing data, the 20 m slope baseline and status, validation results and image paths.

## Repository notes

```text
science/
  profiles/      earth_cells.csv, targets.json, usecases.json, known_analogs.json
  lib/           io_util, power, ndvi, scoring, manifest
  scripts/       run_pipeline, compute_slopes_20m, fetch_site_imagery, fetch_nasa_imagery
  cache/         local API caches (git-ignored)
```

The frontend never calls a live science API. It reads the committed JSON and image assets in `apps/web/public/`.
